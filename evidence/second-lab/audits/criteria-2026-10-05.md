## Verdict scale

| Verdict | Meaning |
|---|---|
| PASS | Every spec-forcing clause of the task is met, proven from bytes (hash or decoded number), not from the agent's words. |
| PARTIAL | At least one spec-forcing clause is met from bytes, but not all. |
| FAIL | No spec-forcing clause is met from bytes, or no program exists. |
| HOST ARTIFACT | The result is decided by a defect of this machine (for example Smart App Control blocks, missing toolchain), not by the agent. |
| UNGRADEABLE | The committed artifacts do not let me apply the criteria. Reason stated. |
| NOT GRADED (discarded) | The directory is marked `_discarded*` by the protocol (harness defect, killed before grading). I list it but do not grade it. |

General rules:

1. An agent's report is evidence about the agent, not the artifact. Self-claims never decide.
2. The final program (`solution.py` / `solution.sh` / the named program) is re-run in a clean scratch directory outside the repo that holds only the fixture and the program. Before any run I read the program and check for network access, subprocess/os.system, deletion, and paths outside its working directory. A program that fails the check is graded from committed artifacts only.
3. Re-runs use Python 3.13 with `PYTHONIOENCODING=utf-8` and `PYTHONUTF8=1`. Reason: the GF harness docstring records S-SFX-4 (a Windows console encoding crash) as a harness defect. If a program passes only with UTF-8 forced, I record that as a note, not a failure.
4. Text clauses (counts, numbers, tool names) are checked in the rerun stdout plus the files the run wrote (REPORT.md, stdout.log). `transcript.json` and `run.json` are EXCLUDED from text scanning, because the transcript contains the inlined context package (which already holds tool sources, layouts and counts).
5. Numeric clauses must be reproduced by the program in my rerun, not only present in a report.

## Task T1: round-1 task (roundOW `__mini`, roundDS `dsv4__mini`, roundXV openai/moonshot crate)

Prompt clauses: open the container, list contents with meanings, verify integrity, extract the primary mesh and one sound; extracted bytes must hash to the declared values.

Measurement: `roundOW/grade.py --rerun` (digest match, name-independent), plus reading rerun stdout.

| Verdict | Condition |
|---|---|
| PASS | Rerun leaves a file whose sha256 == declared `game.glb` AND a file whose sha256 == a declared sound `.wav`, zero mismatched (XX) extracted files, and stdout shows a listing and a per-file hash verification. |
| PARTIAL | Exactly one of mesh / sound matches; OR both match but there is no hash verification in output; OR both match only in the committed state but not on rerun. |
| FAIL | Neither mesh nor sound matches on rerun, or no final program. |

If a roundXV program needs the fixture path as an argument (per its own usage line), I pass `crate-v1.werk` as the only argument.

No committed grader exists. I grade against my own ground truth decoded from `mini-v1.werk` `poses/rest.wkrp` (tools/gt_envelope.py, using the msgpack reader of grade_gsplat.py):

| Clause | Met when |
|---|---|
| C1 integrity | rerun stdout lists entries and reports sha256 verification of declared files |
| C2 decode | rerun stdout names the kind (WKRP or core.pose.rest), the count 2, and at least entry 0's probability 0.62 and quaternion (1,0,0,0), or entry 1's values, to 1e-3. Fabricated values = not met. |

PASS = C1+C2+C3. PARTIAL = C2 met but not all, or C1+C3 met without C2. FAIL = C2 not met and fewer than two clauses met.

## Amendment 2 (2026-10-05, during grading, before reading any verdict)

Reason: the T4 plan assumed WSL gcc. The self-run scripts and recipes target Windows (`win.c` needs `windows.h`), so WSL gcc cannot build them. Found on this host: MSVC 2022 (`cl.exe` via vcvars64.bat) and Git Bash; no mingw gcc and no OpenCV.

Changes to the T4 measurement (the verdict rules are unchanged):

* roundSR codex: rebuild with the exact command in its transcript (`vcvars64 && cl /nologo /O2 /Fe:run.exe tools\llama2c\run.c tools\llama2c\win.c`) in an extracted copy, then invoke with the vector argv.
* roundSR kimi: its recipe is mingw gcc `-static` plus a patch. No mingw here, so the rebuild leg is HOST-BLOCKED.
* GF/DS bash scripts: run with Git Bash (`/usr/bin/bash`, not `bash`, because `bash` on PATH resolves to WSL), with the MSVC environment loaded and `MSYS2_ARG_CONV_EXCL=*` (without it MSYS rewrites `/nologo` into a path). If a script's result depends on which compiler branch the host offers, and the task environment (gcc on PATH) cannot be reproduced here, I record HOST ARTIFACT and state both facts.
* T5 kimi decoder needs OpenCV (`cv2`), which is not installed and would need a download. The decoder rerun leg is HOST-BLOCKED; the committed-bytes grade stands alone and is labelled as such.
