5. HOW THE IMAGE WAS MADE (RECIPE) AND WHAT THE FILE DECLARES (DISCLOSURE)

--- 5.1 The recipe, in plain language ---
    The picture is a 1792x2400 pixel character design plate called 'Ista Varun —
    character design plate'. It was not drawn, photographed or edited by a
    person: it was generated in one shot by a hosted AI image model,
    'gemini-3.1-flash-image', run by Google and reached through the google-genai
    Python SDK's models.generate_content(). The pipeline that called it was
    'visual_bible_engine design_book -> forge.design -> NanoBanana2.design'.

    The model was given two things. First, a long human-written text prompt
    describing the character (a young outer-worlds scholar in austere layered
    robes), the house style register ('realistic detailed colour digital oil
    painting', retro-futurist, in the manner of Hans Holbein the Younger), the
    framing ('centered full-body portrait, the subject fully visible'), the
    palette words (bone white, slate grey, muted bronze) and a long 'Do NOT
    include' exclusion list that keeps other people's franchises and real-world
    political and military insignia out of the picture. Second, one attached
    reference image, the house style plate recipe/inputs/imperial-painterly.png,
    attached automatically because the client's use_style_refs option defaults
    to true. That plate is carried inside this package by hash, so 'what the
    model saw' is not a promise about a file somewhere else.

    The only settings passed were aspect_ratio 3:4, image_size 2K,
    response_modalities TEXT+IMAGE, and a client-side retry policy of up to 4
    attempts with 3.0s backoff. No seed, no sampler, no steps, no cfg, no LoRAs:
    The hosted image API exposes no seed parameter; the call config carries
    aspect_ratio, image_size and response_modalities and nothing else.

    The delivered pixels were written to disk with Pillow's Image.save(), with
    no resize and no crop. So the pixels are the model's and the PNG byte stream
    is Pillow's -- which matters to anyone comparing hashes. The image came back
    at 1792x2400, an aspect of 0.7467 rather than the requested 0.7500, and the
    package records that difference instead of cropping it away. Two later
    files, a 1024-wide preview and a 256-wide thumbnail, are plain Lanczos-3
    downscales of that source and are marked 'measured' because they genuinely
    are reproducible from it.

    REPRODUCIBILITY: the recipe is graded 'descriptive' -- the weakest of the
    three grades -- and the file says exactly why: The model is hosted: no
    weight file exists to hash, the API exposes no seed, and the operator may
    change the weights behind the id 'gemini-3.1-flash-image' without notice.
    Re-running this recipe would produce a different image that follows the same
    instructions.

    THE PROMPT IS TWO DIFFERENT CLAIMS, and the package keeps them apart:
    recipe node v1 (superseded, kept) carries recipe/prompt-recorded.txt -- the
    string the producing pipeline actually persisted. recipe node v2 (active)
    adds recipe/prompt-transmitted.txt, marked provenance 'reconstructed',
    because an audit of the pipeline's source showed the string that was SENT is
