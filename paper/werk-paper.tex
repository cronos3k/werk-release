\begin{abstract}
\noindent
Asset formats rot. They rot because the knowledge required to read a file lives
outside the file: in a companion directory, in an application's undocumented
encoder, in a wiki that has since vanished, in one engineer who has since
retired. The bytes survive; the ability to use them does not. We argue that the
arrival of language-model agents as first-class producers and consumers of files
turns a previously untestable design virtue into a \emph{measurable property}:
given a file and nothing else --- no web, no library, no prior familiarity ---
can a fresh agent write a correct reader for it? We call this
\textbf{agent-implementability}, and we make it a format's acceptance gate rather
than its marketing copy.

We present \textbf{werk}, a container doctrine built to be measured this way.
A werk file is hermetic (no external references), self-describing (it carries its
own narrative specification, JSON Schemas and byte-level layout grammars),
self-historied (multiple coexisting node versions, each with a mandatory work
note) and self-attributed (an append-only Ed25519 custody chain with an explicit
three-state doctrine and no enforcement mechanism of any kind).

The experiment is the paper's heart. In round~1, four fresh isolated agents in
four languages (Python, JavaScript, Rust, C) were handed one 13\,MB package and
the instruction to open it, list it, verify it and extract from it. All four
succeeded: 486\,s, 519\,s, 755\,s and 806\,s, median 637\,s. \textbf{None of the
four used the readers bundled inside the file} to learn the format; the two that
looked at one did so only after their own reader already ran clean. Twelve
distinct specification bugs were surfaced. In round~2, on a second profile
carrying a custom binary payload, two agents parsed the binary envelope, stated
the file's AI-generation recipe and disclosure correctly, and
\textbf{recomputed an embedded image descriptor bit-exactly from the source
pixels} using only the in-file layout grammar --- one of them then implementing
Ed25519 from the embedded mini-specification and reporting
\code{signed-and-valid}, while the other declined the curve arithmetic and
correctly reported \code{signature-unverified}.

Around that experiment we report four independent consumers, each with a measured
gate: a Rust reference core (10/10), a game engine (3.7$\times$ faster cooked-tier
load, cross-validated by a reader that has never heard of it), a Blender add-on
(16/16, deterministic writer, $8.4\times10^{-8}$\,rad rig round-trip), and an
Unreal Engine plugin (16/16, pixel-identical texture round-trip). We report an
unattended enrichment pipeline (19/19 with 78/78 input-hash recomputations) and a
content-defined-chunking store (1.45$\times$ dedup, 94.7\,\% boundary stability).
And we report, at length, what none of this establishes: $n=1$ per language per
round, a single model family, a lost transcript, a vision path that never once
completed, and a generated image that violates its own prompt's exclusion list ---
which an agent correctly read as evidence that a recipe records instructions, not
guarantees.
\end{abstract}

\section{Introduction}

\subsection{The failure mode}

A modern digital artifact is usually a promise about other files. A mesh promises
materials it does not carry. An engine asset promises fifty siblings in a
sidecar directory. A document promises fonts. A video promises a codec. And every
one of them promises a \emph{program}: some specific application, at some
specific version, on some specific machine, without which the bytes are noise.

This is not an aesthetic complaint. It is the mechanism by which formats die.
The applications rot, the documentation vanishes, the one engineer who knew the
quirks retires, and the bytes remain, mute. The failure is not that the data was
lost --- the data is right there --- but that the \emph{knowledge required to
interpret} the data was never stored alongside it.

Existing interchange formats attack part of this and share one shape of gap,
examined in \S\ref{sec:related}: the file is complete about its \emph{bytes} and
incomplete about its \emph{meaning}.

\subsection{Why this is newly measurable}

The usual defence of a well-documented format is a claim of the form ``a
competent engineer could implement this from the specification.'' That claim has
never been cheap to test. Hiring four engineers who have never seen your format,
isolating them from the internet, and paying for a week of their time in order to
find out whether your section 4.4 has an arithmetic error is not a practice any
format has ever been able to afford, which is why no format has ever done it.

Language-model agents change the economics. An agent can be instantiated fresh,
denied network access, pointed at exactly one file, and asked to produce a working
program --- repeatedly, in several languages, for the cost of a few hours of
compute. The question ``can an isolated intelligence write a correct reader for
this file, from the file alone?'' stops being a rhetorical virtue and becomes a
\emph{measurement with a number attached}.

That measurement is what this paper is about. We claim three things:

\begin{enumerate}[leftmargin=1.2em,itemsep=1pt,topsep=2pt]
\item \textbf{Agent-implementability is a well-defined, repeatable format-quality
metric.} It has a protocol, a success criterion, a failure taxonomy, and a
falsifier.
\item \textbf{It is a metric a format can be designed \emph{against}.} We present
werk, a container doctrine of twelve laws whose acceptance gates are stated in
terms of it, and whose specification is required to travel inside every file it
describes.
\item \textbf{The failures the metric produces are its product.} Every agent
stumble in this work became a specification fix, tracked in an append-only
findings ledger. Thirty-eight reported stumbles deduplicated to twelve distinct
specification bugs in round~1 alone; the single most expensive one --- three
agents, three languages, no contact between them, the same longest detour --- was
a two-byte ambiguity in a hashing rule that no amount of internal review had
caught in a year of writing.
\end{enumerate}

\subsection{What is new here, and what is not}

Hermetic packaging is not new (USDZ, OCI images, self-extracting archives).
Self-describing serialisation is not new (JSON, ASN.1, FlatBuffers with reflection).
Cryptographic provenance for media is not new (C2PA). Content addressing is not
new. What is new is (a) the combination held to a constitutional rule --- ``a
werk answers every question it raises'' --- and, more importantly, (b) the
proposition that \emph{whether a format actually achieves this is an empirical
question, answerable by experiment, and that the experiment should be part of
conformance}. This is a technical report on a system built and measured over a
short, intense development period, not a controlled study; \S\ref{sec:limits}
states the limits at greater length than convention would, because a paper
arguing for honesty about what is known cannot practise otherwise.

\section{Design: the twelve laws}

werk is deliberately not a file format. It is a doctrine for building file
formats: twelve laws that govern every concrete \emph{profile}. Profile~1 is a
3D entity; profile~2 is an image. The laws mention no triangles, and both
profiles instantiate them unchanged. Table~\ref{tab:laws} states them in brief.

\subsection{Container and self-description}

A werk package is a directory tree; the interchange form is that tree zipped,
extension \code{.werk}. Both forms are the format. Compression defaults to zip
\emph{store} mode, for one reason that is entirely about law~10: a
zero-dependency zip reader is roughly a hundred lines in any language
\emph{without} an inflate implementation, and several hundred more with one. The
payloads that dominate a package's size (PNG, WAV, GLB) are already internally
compressed, so deflating the container buys single-digit percentages on the bytes
that matter. Cross-file redundancy is the companion store's job (\S\ref{sec:store}),
not the format's.

Self-description is three-layered. \code{spec/SPEC.md} is the narrative
specification of the profile. \code{spec/schemas/*.json} are JSON Schemas
(draft~2020-12) for every structured node, stored as ordinary data. And
\code{spec/layouts/*.layout.txt} are plain-text layout grammars for every custom
binary: endianness, alignment, offsets, types, counts, field semantics, precise
enough to write a parser from scratch. Where a boring ubiquitous encoding exists
(PNG, WAV, GLB, JSON, UTF-8, CRC-32, zlib, SHA-256, Ed25519), werk uses it
\emph{and still embeds a byte-level mini-specification with test vectors}, so
that law~2's guarantee holds literally rather than approximately. That decision
is the one the experiment vindicated hardest: in round~1 no agent needed anything
external for the zip container, CRC-32, SHA-256, WAV, GLB, PNG, JSON, UTF-8, the
manifest structure, the node graph, the edge semantics, the version-resolution
rules, the three signature states, the refusal scopes, or the exit statuses.

\subsection{Islands and graceful degradation}

Every node is an island: self-contained, meaningful alone, never reaching into
another node's bytes. Cross-references go through the manifest by identity. Edges
are typed \code{requires} or \code{enhances}, and almost everything is
\code{enhances}. Corruption is quarantined per node --- hash mismatch marks the
node dead, logs a report entry, and continues. Unknown-because-newer and
unreadable-because-broken degrade through the same code path, which is what makes
law~12 free rather than expensive.

The operational meaning of ``refuse, do not guess'' was itself a specification
bug, found by two independently written bootstrap readers and ruled during this
work. Refusal now has three \emph{scopes}, and a reader picks the smallest that
contains the problem: \textbf{value} (one field), \textbf{node} (bytes, envelope,
schema, or a \code{requires} edge failed), and \textbf{container} (not a zip, no
end-of-central-directory record, zip64 in a zip32-only reader, or an unparseable
manifest --- the only scope permitted to come back empty-handed). Command-line
exit status is pinned to the same taxonomy: 0 opened with no error entry, 1
opened with at least one error entry, 2 container-scoped refusal.

\subsection{Epistemic provenance}

Law~5 is the one that most directly attacks the ``silently wrong answer'' class of
bug. Every derived node records its producer (tool, model, version), its ordered
input files, its input parameters, and a hash over both --- and carries an
epistemic stamp of \code{authored}, \code{measured} or \code{inferred}. An
inferred value is useful \emph{because} it is labelled inferred; laundering it
into fact is the failure.

Crucially this is machine-enforced rather than hoped for. The manifest schema
carries an \code{if}/\code{then}: a stamp of \code{measured} or \code{inferred}
\emph{requires} \code{input\_hash} and an \emph{ordered} \code{input\_files}
array, because an unordered input set cannot produce a reproducible hash. Two
independent adapter authors (Blender, Unreal) independently attempted to stamp an
authored artifact as \code{measured} and were rejected by the schema rather than
by a reviewer --- in both cases correctly, because a live scene is not a file in
the package and there is nothing to recompute against.

The payoff is that stale derived data is detectable from the file alone. In the
enrichment pipeline (\S\ref{sec:pipeline}), all 78 stamped-derived node versions
across three packages had their \code{input\_hash} recomputed \emph{from the
packages' own bytes} by the acceptance gate: 78/78 matched.

\subsection{Versions in the file, and the signature chain}

A node may hold multiple coexisting versions, append-only, with one \code{active}
pointer that is the author's recommendation and not a command. Every version
carries a mandatory work note --- one sentence of why it exists --- as payload,
not tooling metadata. Old versions are never rewritten; compaction is an
explicit, signed, logged choice.

Authorship is an append-only Ed25519 chain. Each entry signs the manifest hash,
and the manifest hashes every file, so a signature covers the entire package state
transitively. Conformant tools must surface three states:
\textbf{signed-and-valid}; \textbf{absent} (anonymous, by choice or by stripping
--- nothing breaks, but the absence is visible); and \textbf{present-and-invalid}
(tampering under an existing signature: the state that catches bad actors). A
fourth fixed token, \code{unverified}, exists for a reader that did not check, so
that declared narrowness is available and silent narrowness is a bug.

The distinction that four independently written readers got right without being
told, and that we had flagged as the easiest thing to get backwards, is this:
\textbf{corrupting a payload does not invalidate the signature} (the chain signs
the manifest; the manifest hashes the files; detection belongs to the per-file
hash), while \textbf{corrupting the manifest does}, under a different report code.

\subsection{Disclosure without enforcement}

Profile~2 introduced two base-doctrine node types that every profile inherits:
\code{core.recipe} (the full reproduction record --- models with weight hashes
where they exist, prompts as files rather than strings, seeds, samplers, LoRAs by
hash, tool versions, every input medium by hash, and a declared reproducibility
grade) and \code{core.disclosure} (machine-readable facts about synthetic
content).

\code{core.disclosure} carries \emph{no enforcement of any kind}. The format ships
facts; the viewer applies its own jurisdiction; a viewer that ignores every
disclosure field is still conformant. The schema's \code{jurisdiction\_note} field
exists precisely so that authors stop writing that sentence into free text where
no reader can find it, and its own description forbids a tool from reporting
compliance on the strength of it. Section~\ref{sec:related} contrasts this with
C2PA, whose provenance model is coupled to an enforcement and trust-list
apparatus.

One design decision inside \code{core.recipe} is worth naming because it is the
single hermeticity exception in the whole doctrine. Input \emph{media} MUST be
embedded in the package and listed in the recipe node's own \code{files[]}. Model
\emph{weights} may be named by hash without being carried, and a recipe that does
not carry them must say so rather than stay silent. A 12\,GB checkpoint inside
every generated image is not a format; and the distinction is not arbitrary,
because input media are small and they are the thing the model actually saw.

\section{Method: the agent gauntlet}
\label{sec:method}

\subsection{Protocol}

The protocol is deliberately blunt. A conformance fixture is copied to a neutral
directory outside every project repository. A fresh agent is instantiated with
its own workspace and given one task sentence, verbatim:

\begin{quote}\small
\emph{Here is a file:} \code{...\textbackslash{}crate-v1.werk}. \emph{Write a
program in $\langle$L$\rangle$ that opens it, lists its contents with their
meanings, verifies integrity, and extracts the primary mesh and one sound to
disk. You may read anything inside the file. You may not search the web or read
anything outside the file.}
\end{quote}

Isolation is enforced as a hard constraint: the only permitted input is that file
and its contents; the project repositories and any \code{spec}/\code{werk}/\code{loaders}
directory elsewhere on the machine are off limits; web search and web fetch are
forbidden; and \emph{recognising the format from prior knowledge does not license
using it} --- everything must be derived from the file.

Success is not self-reported. An agent succeeds if its program opens the
container, lists the node graph with meanings, verifies every declared hash,
extracts the named payloads, and the extracted bytes hash to the values the
manifest declares. In round~2 three further clauses were added: parse the custom
binary payload and print what is inside it; state in plain language how the image
was generated; and state what the file declares about that generation.

\subsection{What is recorded}

Five things: success or failure; wall-clock time to a working reader; whether the
agent used the readers bundled \emph{inside} the file; whether the agent wanted
anything from outside the file; and every stumble, deduplicated into distinct
specification bugs.

The third is the load-bearing one. Every werk package embeds \code{core.loader}
nodes --- single-file, zero-dependency bootstrap readers in Python, Rust and C ---
as payload. If agents learned the format by reading those, the experiment would be
measuring ``can an agent port a program,'' a different and much easier question.
The metric means what we claim only if the \emph{specification} is the path of
least resistance.

\subsection{Deviations, recorded rather than hidden}

Three, and the first matters most.

\textbf{(1) The task sentence was not literally the only text.} Each agent also
received the isolation rules above, a workspace path, a timing instruction, an
instruction to report stumbles honestly, and one environment note (this host's
MinGW gcc fails silently under one available shell --- a sandbox artifact that
would otherwise have been recorded as a format failure). The task sentence itself
is verbatim.

\textbf{(2) The reporting instruction is not neutral.} Agents were told that a
stumble is worth more than a clean run and that under-reporting to look competent
would corrupt the experiment. This inflates the stumble count relative to a silent
run --- which is the intent, since the stumbles are the product --- and it means
the count is not comparable to one gathered without that instruction.

\textbf{(3) The damaged fixture was never handed out in round~1.} The brief called
for re-running two agents against a deliberately corrupted copy. In the event all
four synthesised their own damage without being asked, so there was nothing left to
re-run. That is a stronger result than the brief asked for and a weaker one than it
specified: nobody was tested against damage \emph{they did not design}.

C++ was in the brief's language list and was not run in round~1. It is covered as
a \emph{consumer} by the three-face test of the reference core (\S\ref{sec:core})
and remains untested as an \emph{implementer}.

\section{Results, round 1: four languages}
\label{sec:round1}

\subsection{Setup}

The artifact under test was \code{fixtures/crate-v1.werk} as it stood on
2026-08-08: sha256 \code{93d16579...5a384}, 13\,262\,619 bytes, 157 zip entries,
36 nodes, 155 declared files. It is a wooden crate with a complete sound world,
built from a real production run of a separate 3D-to-audio pipeline, not a
mock-up: 272 vertices and 408 triangles of source geometry, a minimal bounding
sphere of $r = 0.8893$\,m computed by Welzl's algorithm and checked against all
272 points, 20 audio effects (17 interaction plus 3 ambience) across 73 WAV files,
six rendered orbit views and ten segmentation crops carried as \code{x.*}
extension nodes, and one signature chain entry. Its preview prefix --- manifest,
signature, licence, readme, all three bootstrap loaders, the whole of
\code{spec/}, the semantics node and one audible one-shot --- was 723\,944 bytes,
5.46\,\% of the archive.

The fixture has since been rebuilt several times as specification fixes landed;
\S\ref{sec:reverify} re-measures the shipped fixtures at writing time and
\S\ref{sec:limits} records the bookkeeping problem that created.

the report of a real specification bug.

Second, \textbf{the slowest agent was the most thorough one}, and the fastest was
not the least. Wall-clock time here spans reading, writing, compiling, debugging
and report-writing for a whole agent session. It is not time-to-first-parse, and
it is not comparable to a human baseline that was never measured.

\section{Results, round 2: the custom binary}

Round~1's own verdict was that its fixture carried no custom binary, so the entire
binary-envelope apparatus went untested: two agents wrote envelope parsers from
the specification and never got to run one. Round~2 exists to close exactly that
gap, on a second profile, with a longer task list.

\subsection{Setup}

The artifact was \code{ista-varun-v1.werk}, profile \code{image/1}, 15

package's own builder had previously measured a worst drift of $1.381\times10^{-8}$
against the same declared $10^{-6}$; the agents did better than the builder,
which is the correct direction for that particular surprise.

\subsection{Comprehension, not merely parsing}

Both agents stated the recipe and the disclosure correctly, including the parts
that limit what may be claimed. The Python agent reconstructed the v1/v2 prompt
split unprompted, printed the byte-level difference (1\,716 $\rightarrow$ 1\,816
characters), and repeated the file's own caveat that the v2 prompt is
``RECONSTRUCTED, not recorded''. On disclosure it produced the doctrine without
being told it:

\begin{quote}\small
``the format ships facts, the viewer applies jurisdiction, and the format contains
no enforcement of any kind. Nothing here obliges any viewer to do anything; a
viewer that ignores every field above is still conformant. What this program must
not do is paraphrase the claim into a different one.''
\end{quote}

\noindent It also drew, unprompted, the two distinctions the specification cares
most about: that the chain verifies but its key is a published development key
with no external root of trust, so the declared author ``is an assertion by a
party and must not be presented as verified authorship''; and that the package's
C2PA export node ``is a DECLARED BUT UNIMPLEMENTED mapping and proves nothing
about C2PA interoperability''.

The Rust agent produced the observation we consider the most valuable single
sentence either round generated, and it is not about parsing at all. The recipe's
prompt carries an exclusion list --- among other things ``no militaria'' --- and
the delivered image contains uniformed figures with plumed helmets and
epaulettes. The agent's reading:

\begin{quote}\small
``That is the DESCRIPTIVE grade doing exactly what the recipe warns it does ---
the recipe records the instructions, not a guarantee about the pixels.''
\end{quote}

\noindent A reader with no context inferred, from a declared reproducibility grade
alone, the single most important thing a recipe does \emph{not} promise. We
report this as a positive result about \code{core.recipe} and as a permanent
caveat about all recipe data everywhere: a recorded prompt is evidence of intent,
never of outcome.

\subsection{S-10: the finding of the run}

Three agents, three languages, no contact with each other, and the \emph{same}
longest detour. All three read the sentence ``followed by the UTF-8 bytes of the
canonical JSON of \code{input\_params}'' the natural way --- no params, append
nothing --- and all three got \textbf{0 of 25} hashes right.

The Python agent brute-forced ten candidate conventions against three known
targets before finding it. The Rust agent found it by discovering
\code{h.update(b"\{\}")} inside a generator script that happened to travel in the
package, and noted that the generator and the fixture disagreed about whether the
field was even present. The JavaScript agent brute-forced it too.

Two things make this the most valuable result of round~1. First, \textbf{the
bundled loaders could not have saved anyone}: none of the three implements
\code{input\_hash} at all, and two agents checked and said so. Second, \textbf{it
is exactly the failure mode the format claims to prevent}. The package's
\code{spec/README.md} lists ten questions the folder must answer alone; question
six is ``\emph{Is this derived data stale? Recompute} \code{input\_hash} \emph{from}
\code{input\_files} \emph{and compare}.'' It was the one of the ten the folder
could not actually answer.

The ruling: an absent \code{input\_params} \emph{is} the empty object, its
canonical JSON is the two bytes \code{\{\}}, and they are appended exactly as if
the key were written out. Nothing is ever appended as nothing. The rule is now
stated with executable pseudocode and a worked example checkable by hand against
the package itself, writers are told to emit \code{"input\_params": \{\}}
explicitly, and both werk writers do. The fix is verified: a later independent
implementation (the game-engine reader of \S\ref{sec:cub}) implemented the rule
straight from the pseudocode with no detour at all.

\subsection{S-12: ``use a library'' is unfollowable}

All four agents hit this one. The embedded mini-specification said, of Ed25519,
``Do not implement this from a description; use a library'' --- while the format's
own thesis is that an isolated intelligence has no library to reach for, and the
specification separately forbids the embedded Rust and C loaders from having one.
Three agents implemented it anyway; the fourth supplied a DER prefix from memory
and proved the guess against the file's own vector.

The ruling keeps the advice --- it is correct, and a subtly wrong signature check
is worse than none --- but makes the file sufficient. The mini-spec now carries
$p$, $d$, $L$, $\sqrt{-1}$, the base point definition, point encoding and
decompression, the extended twisted-Edwards group law, the canonical-$S$ check,
both verification equations, the SubjectPublicKeyInfo DER prefix, and a statement
that \emph{signing} is deliberately out of scope because key handling belongs in
an audited library. Round~2 measures that fix: one agent built verification from
the file and one declined it correctly, and neither wanted anything from outside.

\subsection{The ledger, and a process failure in it}

Findings are tracked in an append-only ledger: eight from the first two
independently written bootstrap readers (S-1\,\dots\,S-8, all resolved), the
golden-sample finding S-9, round~1's twelve, five from the retarget work, eight
from the enrichment pipeline, six from the Unreal adapter, two from the store, one
from the Blender adapter, four from profile~2 and round~2, and one still open.

The ledger itself produced a finding about ledgers. Three development stages ran
concurrently against one working tree, and each allocated ``the next free finding
number'' from the tree as it stood when it started. All three picked S-22 and two
picked S-23. The reconciliation table is kept rather than quietly renumbered,
because the old labels are in commit messages that cannot be edited, and the rule
applied is that the earliest commit keeps the number. The process lesson is worth
more than the table: \emph{a monotonically increasing counter kept in one prose
document is not a concurrency-safe allocator}, and three agents proved it in one
afternoon. Later stages label findings by stage and ordinal (S10-4) so that
collision is impossible by construction.

\subsection{The reference core, and three faces of one DLL}
\label{sec:core}

\code{werk-core} is a Rust \code{cdylib} behind a C ABI. C++ consumes header plus
DLL; Python binds by \code{ctypes} over the same DLL; there are no package-manager
dependencies anywhere in the consumption path. On conformance fixture~\#1
(413\,741 bytes, 28 zip entries, 15 nodes, 26 declared files), all three faces
report the same 15 nodes, the same 14-alive/1-skipped split, the same
\code{signed-and-valid} verdict, and the same manifest sha256, over one
879\,616-byte \code{werk.dll}. Round-trip byte-identity holds three ways --- from
the zip, from the committed directory form, and from a freshly materialised
directory --- because the physical entry order is a pure function of the manifest
and the zip writer uses a fixed DOS timestamp.

The damage gauntlet asserts \emph{exact} reports and \emph{exact} survivors rather
than ``did not crash''. Four scenarios: a flipped texture byte plus a deleted
semantics file (two nodes dead, eleven alive; a material that merely
\code{enhances} the dead texture survives and reports it); a corrupt mesh (two
nodes die through \code{requires} edges while a node that only \code{enhances} it
stays alive); a schema-invalid payload that was \emph{re-hashed}, so only the
schema can catch it (zero hash mismatches, \code{payload-schema-invalid}); and a
corrupted binary envelope header (\code{envelope-invalid}, one node dead).

Separately, three single-file zero-dependency bootstrap readers ship \emph{inside}
every package as \code{core.loader} nodes. On fixture~\#1 all three verify 26/26
files across 15 nodes standalone, sharing no code with each other or with the
core: \code{werk\_read.py} under stdlib only, \code{werk\_read.rs} under bare
\code{rustc} with \code{-D warnings}, and \code{werk\_read.c} under both
\code{gcc -std=c99 -Wall -Wextra} and MSVC \code{/W3}, with byte-identical output.

One measurement in this stage proves that the code and the specification agree
rather than merely coexist: the fixture's binary rest-pose payload, produced by
the Rust envelope writer, is \textbf{byte-identical} to the example payload the
specification's own generator script produces --- 560 bytes, same sha256, and the
same value the specification's annotated hex dump records. Header length, the
fixed-point iteration on it, the 16-byte alignment, the section offsets and the
trailing padding all agree exactly.

\subsection{Unreal Engine: and the bug only rendering could find}

The Unreal adapter is an editor-only UE5 plugin with two directions: import a
\code{.werk} into real engine assets, and export selected assets plus their real
dependency closure into a conformant unsigned package. Both a real UE~5.7
toolchain and MSVC~2022 build tools were present, so the strong gate ran: the
plugin compiled, and the import commandlet ran against the golden fixture with
exit 0 --- 36 nodes, 25 imported, 11 skipped, 0 refused, 22 assets, 22 packages
saved, \textbf{164 files hash-verified}, signature reported \code{unverified},
0.382\,s inside the facade. The damaged fixture returned \textbf{exit 1}, which is
correct rather than a failure, with one node refused, 21 assets still created, and
the unknown-because-newer node reported as unknown rather than as broken.

Round trip: 272 verts / 408 tris in, \textbf{272 / 408 out}, identical engine-space
axis-aligned bounding box, and the WAV \textbf{byte-identical}. Three independent
readers agree on the exported package: the adapter's own engine-free core (9 PASS,
0 FAIL), the unrelated \code{werk\_read.py} whose independently computed manifest
sha256 matched to the character, and a standard JSON Schema validator against the
schema the package carries, with \textbf{0 errors}.

A second pass closed the texture gap, and its gate is \textbf{16 PASS, 0 FAIL}
including all three textures round-tripping \textbf{pixel-identical} --- while the
gate simultaneously prints that PNG \emph{bytes} are identical for \textbf{0 of 3},
because two different PNG encoders will not agree on bytes and calling that a
failure would be dishonest. Pixels are the claim.

The most important result of this adapter is a bug, S10-6, and it is the argument
of the whole project turned on its author. Setting a mesh's UV channel count
\emph{invalidates} a UV attribute reference taken before it. Writing through the
stale reference raised no assertion, logged no warning and returned no error, and
the mesh came out with \textbf{every UV at $(0,0)$}. Every count in every report
stayed correct --- 730 verts, 408 tris, three textures imported, three slots bound,
three switches on --- and the crate rendered as one flat texel of its own albedo.
It was invisible from inside the adapter and invisible in the package: the
round-trip \emph{pixel} comparison passed, because the texture bytes were never the
problem.

\textbf{The only thing that found it was pointing a camera at it.} The general
lesson is the one this paper is otherwise arguing for a format:
\emph{a report is not a measurement}. Everything the adapter said about that
import was true, and the import was wrong. The regression test is now a number
read back off the artifact --- the measured UV extent of the built mesh --- and
not a count of things attempted.

Two smaller findings of the same family were recorded alongside it: an engine
material-assignment call that silently does nothing on a freshly built mesh with
an empty material array while the importer reported ``assigned to 1 mesh''; and a
material-graph connection API that returns false and logs nothing when it cannot
find a named input, producing a master material that compiled fine, listed every
parameter correctly, and rendered black.

\subsection{The companion store}
\label{sec:store}

Law~1 forbids the \emph{format} from being clever about redundancy; the companion
doctrine puts that cleverness in a version-control store, under a strict ordering
of authority: the materialised package is truth, the store is a cache. The store
is Python with \emph{zero} third-party dependencies, including the cryptography.
On a real production corpus (a 43\,MB photogrammetry mesh, a JPEG texture set, six
rendered views, sixteen recorded WAVs) with a real append-only edit, whole-blob
content addressing measured a dedup ratio of \textbf{1.9970$\times$}, a marginal
ingest cost for the second version of \textbf{0.2404\,\%} of its own size, and a
sync to a store already holding v1 that moved \textbf{0.27\,\%} of v2's bytes.
Both packages materialise \emph{identical to the originals} under a whole-tree
hash comparison against the source directories.

Content-defined chunking (a FastCDC-style Gear chunker, 64\,KiB/256\,KiB/1\,MiB,
whose gear table is derived deterministically from SHA-256 so that a foreign
implementation needs one sentence rather than 256 constants) was then measured on
the conformance fixture corpus plus a 4096-byte edit at a fixed offset of the
corpus's largest payload:

\section{Limitations}
\label{sec:limits}

This section is longer than convention would have it, because the format's
central claim is honesty about what is known, and a paper about that format
cannot practise otherwise. Everything here is a real limit on the results above.

\subsection{Limits on the experiment}

\textbf{$n = 1$ per language per round.} Round~1 is four data points and round~2 is
two. A success rate of 4/4 is consistent with a true rate anywhere above roughly
40\,\%. This design can rule out a bad format; it cannot distinguish a good one
from a lucky one.

\textbf{One model family.} Every agent in both rounds is from the same model
family. A shared blind spot would look exactly like a shared success. The one
place this is visible is Ed25519: three of four round-1 agents reached for
constants they already knew, and only the file's own test vector caught whether
they were right. Testing at least one non-Claude model has been the stated ``next
honest step'' since round~1 and remains untaken.

\textbf{Recognition is not fully excluded.} Agents were instructed to derive
everything from the file and their logs are consistent with that, but zip and glTF
are ubiquitous. The JavaScript agent wrote its zip reader from prior knowledge
\emph{before} opening the specification and said so. What that measures is that
the specification \emph{retro-confirmed} a from-memory implementation and caught a
gap in it (zip64) --- a weaker but still real result.

\textbf{The stumble count is instruction-inflated}, by design, and is therefore
not comparable to a count gathered without that instruction.

\textbf{Timing is wall-clock over a whole agent session}, including reading,
writing, compiling, debugging and report-writing. It is not
time-to-first-working-parse, and there is no human baseline: we did not measure
one, and until someone does, the times in Table~\ref{tab:r1head} are internally
comparable and externally meaningless.

\textbf{Fixture gaps were closed only progressively.} Round~1's fixture carried no
custom binary at all, so the entire envelope apparatus --- the layout grammar, the
MessagePack subset, the section consistency rule --- went untested by that round;
two agents wrote envelope parsers and never got to run one. Round~2 closed that
and opened others: it ran no damage gauntlet at all, tested no zip64 container, no
deflate container, and no package with more than one kind of custom binary. No
zip64 fixture exists anywhere in the project, so every zip64 path any agent or
implementation has written is unexercised code.

\textbf{Two harness failures, counted as harness failures.} The first round-2 Rust
agent died 21 minutes in, after building a complete 3\,520-line reader across eight
modules and extracting the payloads, without delivering a report. Its workspace
survives and shows how far it got; its report does not exist. It is counted
\emph{neither as a success nor as a failure of the format}, and the run was
repeated fresh --- a new agent in a new workspace, never a resume. Separately, the
harness wrote both round-2 agents' task transcripts as \textbf{zero-byte files}, so
the per-agent process data round~1 collected --- the order in which resources were
read, per-part timings, whether the bundled loaders were consulted --- cannot be
reported for the Python agent and is marked \emph{not recorded} rather than
guessed. That is the run's own finding about itself: \emph{an experiment whose
evidence lives only in a transcript is one lost file away from being an anecdote.}
The agents' programs and complete outputs are committed, and are the evidence for
everything claimed about them.

\subsection{Limits on the implementations}

\textbf{The vision-language properties path has never completed.} It is
implemented, environment-driven, and was exercised against a real endpoint that
refused every connection --- all three gate runs record the connection refusal
against the configured address. The pipeline did not hard-require it and did not
fail: it wrote a stub carrying exactly one field and a note saying in plain words
that no model was consulted. The model-supplied path is therefore code that has
been run only as far as the socket, and it is the largest untested surface in that
component.

\textbf{Tangents are not MikkTSpace}, and the package says so, declaring an
accumulate-then-Gram-Schmidt basis by name with a note stating exactly where it
diverges (UV chart seams, where MikkTSpace splits a vertex and this does not). The
associated finding, S3-4, records that no geometry node currently has anywhere to
\emph{declare} which tangent algorithm produced its data, so a package whose
tangents are not MikkTSpace is silently inconsistent with a normal map that assumes
they are.

\textbf{The convex decomposition is a measured-worse substitute.} V-HACD proper is
roughly 6\,000 lines of C++ and its maintained Python bindings are compiled wheels;
vendoring either would put a build toolchain or an opaque binary into a repository
whose entire argument is that you can read what you depend on. What runs instead is
a declared \code{voxel-hacd-lite/0.1} --- V-HACD's three-step shape without its
plane search, hull simplification or volume-conservative merge. It is a worse
decomposition, the fit method says so, and \emph{both} fit metrics are measured so
a consumer can see how much worse: Hausdorff 0.157--2.002\,m and volume ratios of
2.0--3.8 rather than near 1.

\textbf{Frame invariance has a measured exception} (S6-3), stated in
\S\ref{sec:ecosystem}: $0.2217$\,rad of frame-dependent error where a foreign rig
interposes an animated joint, against $3\times10^{-14}$ where it does not, and no
way in the format to say which interposed joints are artefacts and which are real
motion.

\textbf{Half a gate is measured for the engine consumer.} Its acceptance criterion
names load time \emph{and} frame time; only load time was measured. Nothing in that
work has been through a renderer: no GPU upload, no draw call, no frame. The
cooked tier's frame-time claim is plausible and untested, and the engine-scale
instancing test with imposters and LOD selection did not happen at all, because the
golden fixture carries neither.

\textbf{Coverage gaps that are real rather than rhetorical.} One Blender version on
one operating system; one build target for the reference core; no deflate and no
zip64 support anywhere (both detected and refused by name); no skeleton or
animation import in the Unreal adapter; no Ed25519 in three of the consumers, each
reporting \code{unverified} rather than guessing; and only three small assets
through the enrichment pipeline, none above 6\,576 triangles.

\subsection{The limit that is a result}

The round-2 fixture's own recipe carries an exclusion list that the delivered
image violates. We could have chosen a fixture without that property. We did not,
because the honest reading of it --- supplied unprompted by an agent that had never
seen the format --- is the most useful thing either round produced about recipes:
\emph{a recipe records instructions, not guarantees}. Any system that treats a
recorded prompt as evidence about the pixels is wrong, and the reproducibility
grade in the file is the field that says so.

\section{Related work}
\label{sec:related}

\textbf{glTF~2.0 / GLB} is the closest thing to a universal runtime interchange
format for 3D, and werk uses it: geometry payloads inside a werk package
\emph{are} GLBs, because law~11 prefers a boring ubiquitous encoding over a clever
new one. What werk adds is the layer glTF deliberately does not have: glTF's
semantics live in an external specification and its extension ecosystem is a set
of external agreements, so a GLB does not carry the knowledge of how to read a
GLB. The difference is measurable --- agents here parsed GLB from an embedded
mini-specification without wanting anything external. werk also overrides glTF's
stated forward axis inside a package, because a convention has to be one declared
number rather than two conflicting documents.

\textbf{USD and USDZ} are the industrial answer to scene-scale composition, and
their defining strength --- layered references and overrides across files --- is
structurally the pattern law~1 forbids. This is a difference in purpose rather than
a criticism: USD is a composition system for live pipelines, and werk is an
artifact doctrine for things that must survive their tools. USDZ packages a scene
for delivery; it does not package the specification, the schemas, the readers, the
provenance, the version history or the custody chain, and a USDZ whose authoring
application is gone is in exactly the position this paper's introduction describes.

\textbf{C2PA} is the closest relative on provenance, and the contrast is the
sharpest point of design disagreement in this work. C2PA binds content credentials
cryptographically and derives its meaning from an enforcement-and-trust-list
apparatus: a claim is worth what its signer's position in a trust hierarchy makes
it worth. werk's chain is deliberately \emph{facts-only}. It records who signed
what state, it surfaces three states plus a fourth ``I did not check'' token, and
it enforces nothing --- there is no trust list, no revocation authority, and no
notion of a compliant viewer. The format cannot prevent plagiarism; it makes clean
provenance the cheapest path and its absence conspicuous. Round~2's Python agent
articulated the consequence better than our own specification did: the chain
verifies, but its key is a published development key with no external root of
trust, so the declared author ``is an assertion by a party and must not be
presented as verified authorship.'' The two models are complementary rather than
competing, and the package carries an explicitly labelled, explicitly unimplemented
C2PA export stub rather than a claim of interoperability --- which the same agent
correctly reported as proving nothing.

\textbf{FlatBuffers, Cap'n Proto, Protocol Buffers} and the self-describing
serialisation family solve zero-copy structured access with excellent engineering,
conditional on the consumer possessing the schema. werk's position is that the
schema is part of the artifact: schemas are stored as ordinary data files inside
the package and the manifest names their paths \emph{inside this package}, never
by convention. The cost is duplication --- every conformant writer must vendor a
copy of every schema it emits --- which is finding S-29, filed by the Blender
adapter, whose mitigation (a byte-identical vendored copy, refreshed by one script,
verified by that script's check mode, run as a gate clause) is offered as the shape
of a general answer rather than as one.

\textbf{Content-addressed stores} --- Git, IPFS, OCI, Perforce's and Unity's asset
databases --- solve dedup, transfer and identity, and werk's companion store is
squarely in that tradition, down to sharing the manifest's per-file sha256 as the
store key with no translation layer. The doctrinal difference is the ordering of
authority: the materialised package is truth and the store is a cache, never the
reverse, enforced structurally by making every round-trip assertion compare against
the original on disk and by a test that corrupts the store and requires
materialisation to fail loudly and leave nothing behind. \textbf{Reproducible
builds} and the software bill-of-materials movement share werk's instinct that an
artifact should carry a checkable account of its own production;
\code{core.recipe} and the \code{input\_hash} discipline are that idea applied to
media rather than to binaries, with the one difference that a model's weights may
be named by hash rather than carried.

\section{On the authorship of this work}
\label{sec:disclosure}

This paper is about whether autonomous agents can implement a format from a file.
It would be incoherent to obscure the fact that autonomous agents also built and
tested the thing being measured, so we state it plainly.

The doctrine, the twelve laws, the design decisions, every ruling on a filed
finding, and the acceptance criteria are the author's. The implementation work ---
the reference core, the three bootstrap readers, the enrichment pipeline, the
retarget solver, the store, the Blender and Unreal adapters, the fixtures and the
gate harnesses --- was carried out by Claude agents (Anthropic) working in a loop
against written briefs, under a house rule that nothing advances on assertion and
every gate is a measurement. The gauntlet agents of \S\ref{sec:round1} and
\S\ref{sec:round2} are from the same model family, which is stated in
\S\ref{sec:limits} as the sharpest limit on the experiment's external validity.
The prose of this paper was drafted by an agent from the recorded measurements and
is the author's responsibility.

Three consequences are worth drawing out, because the meta-fact is part of the
result rather than a disclaimer attached to it.

\textbf{First, the separation that makes the experiment valid is not between human
and machine but between \emph{implementer} and \emph{measurer}.} The gauntlet
agents were isolated from the repository, from the web, and from every artifact of
the development process except the single file handed to them. Whether the
implementer of a package's producer was a human or a model is irrelevant to
whether a stranger can read the package; what matters is that the stranger had
nothing but the package.

\textbf{Second, agent-built systems make the ``silently wrong answer'' failure mode
more dangerous, not less}, and this work has the receipts. Five of the Blender
adapter's bugs and three of the Unreal adapter's passed every structural check
while producing wrong data; one was invisible in the package, invisible in the
round-trip pixel comparison, correctly reported by every count in every report,
and found only by pointing a camera at the result. An agent that writes plausible
code and an agent that writes a plausible report are the same agent. The defence
here is structural: gates that assert exact sets rather than absence of crashes,
numbers read back off artifacts rather than counted at attempt time, and
independent readers that share no code grading each other's output.

\textbf{Third, the process failures are as reportable as the results.} Concurrent
agents sharing one working tree collided on a shared findings counter three times
in one afternoon and swept two stages' documents into a third stage's commit
twice. Both are recorded rather than tidied, on the same principle that governs
the format: a history that gets quietly corrected stops being a history.

\section{Conclusion}

Formats die when their knowledge dies. The response proposed here is neither a
better schema language nor a better archive: it is a constitutional rule that a
file must answer every question it raises, plus an experiment that tells you
whether it does.

The experiment works. Six agents across two rounds, four languages and two
profiles, each given one file and nothing else, produced working readers ---
6/6 --- and between them surfaced fifteen distinct specification bugs that
internal review had not. None of them learned the format from the readers bundled
inside the file, which is the single result that makes the metric mean what we
want it to mean. Two recomputed an embedded, epistemically stamped measurement
from source pixels and hit every bit, which turns a claim a package makes into
one a stranger can check. Four spontaneously built damaged copies and each got
right the signature-versus-payload distinction we had flagged as the easiest thing
in the format to invert. And one, from a declared reproducibility grade alone,
correctly inferred the most important thing a generation recipe does not promise.

The honest next steps have not changed since round~1 named them, and they are
named again here because naming them and not taking them is the state of the work:
more agents per language, at least one model family that is not ours, a fixture
carrying zip64 and a deflate container, a damage gauntlet against profile~2, a
frame-time measurement to close the half-measured engine gate, and one vision model
that answers so that an inference path stops being code that has only ever reached
a socket.

What we believe generalises beyond werk is the metric itself. Any format ---
scientific data, documents, model checkpoints, medical imaging --- can be handed to
an isolated agent with the instruction ``write a reader''. The success rate is
interesting. The list of things the agent had to guess is the product.
