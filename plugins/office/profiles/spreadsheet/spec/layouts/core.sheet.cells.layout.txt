core.sheet.cells — layout grammar v1
====================================

The AUTHORED cells of one sheet of a `spreadsheet/1` document: for every stored cell its
position, its constant value, the source text of its formula, and the number of its cell
format.

WHERE THESE BYTES ARE. A sheet's cells are stored in BANDS of rows. Each band is a file of the
node `sheet-<uid>-cells` (`sheets/sheet-<uid>/cells/rows-<first row>.wkx.zlib`) and is ONE
zlib stream (RFC 1950; spec/formats/zlib-deflate.md). This grammar describes a band AFTER it
is inflated. The node's payload, `sheets/sheet-<uid>/cells.json`, is the index that lists the
bands with their rows and hashes (spec/PROFILE-SPREADSHEET.md section 3.3,
spec/schemas/core.sheet.cells.schema.json). A band holds the cells of its rows only, and is
complete in itself: its own string table, its own formula table. Row numbers in it are
absolute row numbers of the sheet.

It is a werk binary envelope. spec/layouts/ENVELOPE.layout.txt is normative for the frame
(magic, version, header length, MessagePack header, 16-byte aligned sections at DECLARED
offsets) and for the MessagePack subset of the header; this file defines only what is specific
to this kind. Read ENVELOPE.layout.txt section 7 (the reference reader) first.

A complete worked example — a real small file, every byte annotated down to the decoded
values — is spec/examples/spreadsheet/cells.example.hex.txt, next to the binary
itself (cells.example.wkx). spec/examples/spreadsheet/read_spreadsheet.py is this grammar as
running code (function `read_cells`), and write_minimal.py writes one (function `cells_file`).

--------------------------------------------------------------------------
1. Frame
--------------------------------------------------------------------------

  magic      "WKX0"   (57 4B 58 30)
  version    1        (u32 LE at offset 4)
  header     MessagePack map. The five mandatory envelope keys, with
               "kind" = "core.sheet.cells"
             and these keys of this kind (all uint):

  key              meaning
  ---------------  -----------------------------------------------------------
  "sheet_uid"      MANDATORY. The uid of the sheet these cells belong to: the
                   <uid> of the node id `sheet-<uid>-cells`. A reader refuses
                   the node when it differs.
  "cell_count"     n, the number of cells (entries of every per-cell section).
  "text_count"     t, the number of strings in the string table.
  "formula_count"  f, the number of entries in the formula table.
  "array_count"    a, the number of entries in the array table.
  "element_count"  e, the number of array elements.

  The counts restate what the section shapes already say; a reader checks
  the SECTIONS and may check the counts against them. A writer may omit every
  count; it may not omit "sheet_uid".

--------------------------------------------------------------------------
2. Sections
--------------------------------------------------------------------------

All sixteen sections are present in every file, in any order (a reader finds a section BY
NAME); a table with no entries is a section of size 0. All integers are little-endian,
unsigned. n, t, f, a, e are the counts above.

  name             dtype  shape     stride  size     one entry per
  ---------------  -----  --------  ------  -------  -----------------------
  row              u32    [n]       4       4*n      cell
  col              u32    [n]       4       4*n      cell
  kind             u8     [n]       1       n        cell
  number           f64    [n]       8       8*n      cell
  ref              u32    [n]       4       4*n      cell
  style            u32    [n]       4       4*n      cell
  formula          u32    [n]       4       4*n      cell
  text-offsets     u64    [t+1]     8       8*(t+1)  string, plus one
  text-bytes       u8     [T]       1       T        byte of string data
  array-dims       u32    [a,4]     16      16*a     array
  elem-kind        u8     [e]       1       e        array element
  elem-number      f64    [e]       8       8*e      array element
  elem-ref         u32    [e]       4       4*e      array element
  formula-offsets  u64    [f+1]     8       8*(f+1)  formula, plus one
  formula-bytes    u8     [F]       1       F        byte of formula text
  formula-array    u32    [f,5]     20      20*f     formula

  Entry i of `row`, `col`, `kind`, `number`, `ref`, `style` and `formula` describe the SAME
  cell, cell i.

2.1 Position: `row`, `col`

  ZERO-based. The cell written "A1" is row 0, col 0; "C7" is row 6, col 2. Valid rows are
  0..1048575 and valid columns 0..16383 (manifest conventions `grid_rows`, `grid_cols`,
  `cell_index_base`). Column letters: 0 = A, 25 = Z, 26 = AA, 16383 = XFD.

  Cells are sorted by row, then by column, strictly ascending: for i > 0,
  (row[i], col[i]) > (row[i-1], col[i-1]) compared as a pair. No position appears twice. A
  reader refuses a file that is out of order (the node is dead), because a duplicate position
  has no defined winner. A cell outside the grid is refused as a VALUE: the reader skips that
  cell, says so, and reads the others.

  Only stored cells appear. A position that is absent is an empty, unformatted cell (its
  format, if any, comes from its row or column record in the sheet node).

2.2 Value: `kind`, `number`, `ref`

  kind  meaning          number           ref
  ----  ---------------  ---------------  ---------------------------------
  0     empty            0.0              0
  1     number           the value        0
  2     text             0.0              index into the string table
  3     boolean          0.0              0 = FALSE, 1 = TRUE
  4     error value      0.0              error code (table below)
  5     non-finite       0.0              0 = NaN, 1 = +infinity, 2 = -infinity
  6     array            0.0              index into the array table

  A number is an IEEE-754 binary64, stored bit-exact as 8 little-endian bytes (1.5 is 00 00 00
  00 00 00 F8 3F; negative zero is 00 00 00 00 00 00 00 80 and stays negative zero). `number` never holds NaN or an infinity: those are kind 5.
  Spreadsheets do not normally hold them; kind 5 exists so that no value an application can
  hold is unrepresentable. A DATE is a kind-1 number of days (see section 4).

  Kind 0 with a `style` is a formatted empty cell. Kind 0 is also what EVERY formula cell
  carries here: the result of a formula is derived data and lives in the sheet's
  core.sheet.computed node, never in this file. A reader refuses a file in which a cell has a
  formula (formula[i] != 4294967295) and kind[i] != 0.

  Error codes (`ref` of kind 4). 1..7 are the numbers the function ERROR.TYPE returns:

    code  text             code  text             code  text
    ----  ---------------  ----  ---------------  ----  ---------------
    1     #NULL!           5     #NAME?           9     #SPILL!
    2     #DIV/0!          6     #NUM!            14    #CALC!
    3     #VALUE!          7     #N/A             15    #CIRC!  (unresolved
    4     #REF!            8     #GETTING_DATA          circular reference)

  Any other code: the reader refuses the node.

2.3 The string table: `text-offsets`, `text-bytes`

  String k (0 <= k < t) is the bytes text-bytes[ text-offsets[k] .. text-offsets[k+1] ),
  UTF-8, no terminator, no byte order mark, any Unicode text including line breaks (U+000A)
  and the empty string. text-offsets[0] = 0, offsets never decrease, and text-offsets[t] = T,
  the size of `text-bytes`. With no strings, `text-offsets` is the single value 0.

  A writer SHOULD store each distinct string once (several cells then share an index), in
  order of first use. A reader accepts duplicates and unused strings.

2.4 The array table: `array-dims`, `elem-kind`, `elem-number`, `elem-ref`

  A cell's value may be a two-dimensional array of values (rare for a constant; common for a
  cached result in the computed node, which uses the same sections).

  Array j is the four u32 values array-dims[j] = (rows, cols, first, count). Its elements are
  elements first .. first+count-1 of the three `elem-*` sections, in ROW-major order (all of
  row 0, then row 1, ...). count = rows*cols in every file a conforming writer produces; a
  reader takes `count` elements and does not multiply. An element is a value encoded exactly
  as in 2.2, with `elem-kind`, `elem-number`, `elem-ref` in place of `kind`, `number`, `ref`.

  An element of kind 6 names another array. It may only name an EARLIER one: an array j refers
  to arrays 0..j-1 only (a writer appends inner arrays before the array that contains them).
  A reader decodes arrays in index order and refuses a reference to an array it has not
  decoded yet — so nesting needs no recursion and cannot loop.

2.5 Format: `style`

  The ZERO-based index of the cell's format in `cell_formats` of the document's
  core.sheet.styles node (node id `styles`). 0 is the default format. An index beyond the
  end of that array means the default format.

2.6 Formula: `formula`, `formula-offsets`, `formula-bytes`, `formula-array`

  formula[i] = 4294967295 (FF FF FF FF): cell i has no formula.
  Otherwise formula[i] = g, an index into the formula table (0 <= g < f).

  The text of formula g is the bytes formula-bytes[ formula-offsets[g] .. formula-offsets[g+1] ),
  UTF-8, with the same offset rules as the string table. It is the formula's SOURCE TEXT
  WITHOUT a leading "=":  `SUM(B2:B9)*2`  — see section 3 for the grammar.

  formula-array[g] is five u32 values (flag, r0, c0, r1, c1):
    flag = 0  an ordinary formula; r0, c0, r1, c1 are 0.
    flag = 1  a legacy ARRAY formula (entered with Ctrl+Shift+Enter): ONE formula computing
              the whole block of cells rows r0..r1, columns c0..c1 (zero-based, both ends
              included, r0 <= r1, c0 <= c1). The formula is stored on the block's top-left
              cell only; the block's other cells are not stored here.
  Any other flag: the reader refuses the node.

  Several cells may share one table entry (a formula filled down a column whose text is
  identical). Two entries may have the same text and differ in `formula-array`.

--------------------------------------------------------------------------
3. Formula text
--------------------------------------------------------------------------

  Formula text is in the grammar the manifest declares: conventions
  `formula_grammar` = "excel-a1-en-us", `formula_leading_equals` = false,
  `formula_argument_separator` = "comma", `formula_decimal_separator` = "period",
  `formula_array_row_separator` = "semicolon". spec/PROFILE-SPREADSHEET.md section 5.2 gives
  the grammar in full (operators and their precedence, reference forms, literals, structured
  references). In short: English upper-case function names, `,` between arguments, `.` as
  the decimal point, A1-style references with ONE-based row numbers (`$B$7`, `Sheet2!A1:C9`,
  `'My Sheet'!A:A`), text literals in double quotes with `""` for a quote, array constants
  `{1,2;3,4}`.

  A formula whose text does not parse in that grammar is still stored, verbatim; it evaluates
  to #NAME?. A reader without a formula engine does not need to parse formula text at all:
  it reads each formula cell's cached result from the computed node.

--------------------------------------------------------------------------
4. Dates and times
--------------------------------------------------------------------------

  There is no date type. A date or time is a kind-1 NUMBER that is displayed as a date because
  the cell's format (section 2.5 → `num_fmt`) is a date format. The number counts DAYS; its
  fraction is the time of day (0.5 = 12:00:00, 0.75 = 18:00:00). Which day is day zero is
  said by `date_system` in the workbook node:

    "D1900"  serial 1 = 1900-01-01. Serial 60 is 1900-02-29, A DAY THAT DID NOT EXIST
             (a historical error every spreadsheet keeps). So:
               serial n >= 61 :  date = 1899-12-30 + n days      (61 = 1900-03-01)
               serial 1..59   :  date = 1899-12-31 + n days
               serial 60      :  shown as 1900-02-29
    "D1904"  serial 0 = 1904-01-01; date = 1904-01-01 + n days. No fictitious day.

  The manifest states the same numbers as conventions (`date_serial_unit`,
  `date_1900_serial_of_1900_01_01`, `date_1900_fictitious_leap_day_serial`,
  `date_1900_serial_of_1900_03_01`, `date_1904_serial_of_1904_01_01`).
  Check: in D1900, serial 45000 is 2023-03-15; 45000.75 is 2023-03-15 18:00:00.

--------------------------------------------------------------------------
5. What a reader does on each failure
--------------------------------------------------------------------------

  not an envelope, wrong magic or kind,       refuse the NODE (it is dead): the sheet
  a section missing or of the wrong dtype,    keeps its name, layout and features and
  per-cell sections of different lengths,     has no cells; say so; load everything
  offsets that run backwards or past the      else.
  data, text that is not UTF-8, cells out
  of order, an unknown kind / error code /
  flag, an index out of range, a formula
  cell with a value, wrong "sheet_uid"

  a cell outside the grid                     skip that cell; say how many were skipped

  an unknown SECTION name, an unknown         skip it and say so (ENVELOPE.layout.txt
  header key, a version above 1               section 5a); never refuse for it

--------------------------------------------------------------------------
6. Writing one
--------------------------------------------------------------------------

  1. Collect the cells, sorted by (row, col). For each: its value triple (2.2), its style
     index, its formula table index or 4294967295.
  2. Build the string table, the array table (inner arrays first) and the formula table.
  3. Lay the sixteen sections out in any order, each starting on a multiple of 16 bytes from
     the start of the file, zero bytes between them; write the header with every section's
     name, ABSOLUTE offset, size, dtype, shape and stride (ENVELOPE.layout.txt sections 3
     and 5), the mandatory envelope keys, and "sheet_uid".
  The smallest legal file is a sheet with no cells: n = t = f = a = e = 0, `text-offsets` and
  `formula-offsets` each the eight bytes 00 00 00 00 00 00 00 00, every other section empty.
