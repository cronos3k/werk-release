werk preview proxy - layout grammar v1  (magic "WKX2", inside a zlib stream)
===========================================================================

Applies to: `core.preview.proxy` (profiles `motion-comp/1` and `timeline/1`,
the same layout in both) - the start of the main composition as a few small
frames of raw RGB, for showing motion without decoding or rendering anything.

THE PAYLOAD FILE IS A ZLIB STREAM (RFC 1950; `spec/formats/zlib-deflate.md`
defines it and carries a reference inflater). What it INFLATES to is a werk
envelope, described here. The node's `meta` gives `inflated_bytes` and
`inflated_sha256`: inflate, check both, then read the envelope.

Read `spec/layouts/ENVELOPE.layout.txt` FIRST. Everything below is the
WKX2-specific part.

--------------------------------------------------------------------------
1. Fixed prefix (of the INFLATED bytes)
--------------------------------------------------------------------------

  [0 .. 4)    magic  = "WKX2"  = 57 4B 58 32
  [4 .. 8)    version : u32 LE = 1
  [8 .. 12)   header_len : u32 LE
  [12 .. 12+header_len)  MessagePack header (section 2)
  padding of zero bytes to the next 16-byte boundary
  the one payload section (section 3)

--------------------------------------------------------------------------
2. Header keys
--------------------------------------------------------------------------

  Mandatory envelope keys: "kind" = "core.preview.proxy", "endianness" = "le",
  "payload_origin", "payload_size", "sections".

  key                 type  meaning
  ------------------  ----  --------------------------------------------------
  "comp"              uint  id of the composition the frames show.
  "width", "height"   uint  size of every frame, pixels.
  "frames"            uint  F: number of frames, 1..36.
  "rate_num"          int   the rate the frames PLAY at, frames per second:
  "rate_den"          int   rate_num / rate_den (the composition's rate
                            divided by "comp_frame_step").
  "comp_frame_step"   int   frame i of the proxy is composition frame
                            i * comp_frame_step.
  "ticks_per_second"  uint  254016000000.
  "pixel_format"      str   "rgb8": three bytes per pixel, R G B.
  "transfer"          str   "srgb": the bytes are in the project's output
                            encoding (sRGB unless the project names another
                            output space), the composition over black.

--------------------------------------------------------------------------
3. Payload section
--------------------------------------------------------------------------

  name      dtype  shape                  stride  arithmetic that MUST hold
  --------  -----  ---------------------  ------  ------------------------------
  "frames"  u8     [F, height, width, 3]  3       size == 3 * F * height * width

  Frame after frame; within a frame row after row from the TOP; within a row
  pixel after pixel from the left; within a pixel R, G, B.

--------------------------------------------------------------------------
