werk baked expression values - layout grammar v1  (magic "WKX4")
===============================================================

Applies to: `core.expr.baked` (profile `motion-comp/1`) - the evaluated values
of the expression-driven properties of ONE composition whose results are
numbers, one sample per sampled composition frame.

Read `spec/layouts/ENVELOPE.layout.txt` FIRST. Everything below is the
WKX4-specific part. What an expression is, when these samples may be used and
when they are stale: `spec/PROFILE-MOTION-COMP.md` section 6.18.

--------------------------------------------------------------------------
0. Why a binary at all
--------------------------------------------------------------------------

One number per property per frame: a ten-minute composition with twenty
expressions is 300 000 numbers. As binary64 they are exactly what the
writing application computed - a reader that evaluates the same expression
can compare bit for bit - and they are 8 bytes each.

--------------------------------------------------------------------------
1. Fixed prefix
--------------------------------------------------------------------------

  [0 .. 4)    magic  = "WKX4"  = 57 4B 58 34
  [4 .. 8)    version : u32 LE = 1
  [8 .. 12)   header_len : u32 LE
  [12 .. 12+header_len)  MessagePack header (section 2)
  padding of zero bytes to the next 16-byte boundary
  the one payload section (section 3)

--------------------------------------------------------------------------
2. Header keys
--------------------------------------------------------------------------

  Mandatory envelope keys, per ENVELOPE.layout.txt section 3:
    "kind"            = "core.expr.baked"
    "endianness"      = "le"
    "payload_origin", "payload_size", "sections"

  Mandatory WKX4 keys:

  key                 type          meaning
  ------------------  ------------  ------------------------------------------
  "comp"              uint          id of the composition.
  "ticks_per_second"  uint          254016000000.
  "rate_num"          int           the composition's frame rate, numerator
  "rate_den"          int           and denominator (frames per second).
  "first_frame"       int           composition frame of sample 0.
  "frame_step"        int           composition frames between two samples, >= 1.
  "samples"           uint          S: samples per track.
  "tracks"            array of map  one entry per sampled property.
  "unbaked"           array of map  the expression-driven properties WITHOUT a
                                    track: {"layer": uint, "uid": uint,
                                    "reason": str}. Reasons: "per-character",
                                    "evaluation-failed", "kind-changes",
                                    "non-finite".

  Each element of "tracks":

  key            type  meaning
  -------------  ----  ---------------------------------------------------
  "layer"        uint  id of the layer the property is on.
  "uid"          uint  uid of the property. (layer, uid) is the track's name.
  "kind"         str   "scalar", "vec2", "vec3", "color", "bool" (each
                       sample 0 or 1) or "enum" (each sample the 0-based
                       index of the choice).
  "components"   uint  numbers per sample: 1, 2, 3, 4, 1, 1.
  "first_value"  uint  index in "value" of the first number of sample 0.

  Sample i of a track is the property's value at the START of composition
  frame first_frame + i * frame_step, i.e. at tick
  ceil(frame * ticks_per_second * rate_den / rate_num), as the writing
  application evaluated it: its keyframes, then its expression.

--------------------------------------------------------------------------
3. Payload section
--------------------------------------------------------------------------

  name      dtype  shape  stride  arithmetic that MUST hold
  --------  -----  -----  ------  --------------------------------------
  "value"   f64    [N]    8       size == 8 * N,
                                  N == sum over tracks of S * components,
                                  or N == 1 when there is no track

  Little-endian IEEE-754 binary64, no NaN, no infinity. A track's numbers
  are consecutive: sample i, component d is at
  first_value + i * components + d. When "tracks" is empty (every
  expression of the composition is listed in "unbaked") the section holds one
  0.0 and means nothing.

--------------------------------------------------------------------------
