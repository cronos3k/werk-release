core.raster.lut3d - layout grammar v1
====================================

Applies to: the one file of a node of type `core.raster.lut3d` in a werk
package of profile raster-layers/1. Magic "WKX1" (57 4B 58 31), envelope version
1, header key "kind" = "core.raster.lut3d".

A 3D colour lookup table: for a grid of input colours it gives the output
colour. It is the table of a Color Lookup adjustment layer; the layer's JSON
payload (`content.adjustment.ColorLookup.lut`) names this node, and repeats the
grid size as `content.adjustment.ColorLookup.size`.

The frame is the werk binary envelope: spec/layouts/ENVELOPE.layout.txt
(sections 1, 3, 4, 7) reads it. This file says what the header keys and the one
section mean. Worked example, every byte annotated:

    spec/examples/raster-layers/lut3d.example.wkx
    spec/examples/raster-layers/lut3d.example.hex.txt

--------------------------------------------------------------------------
1. Header keys
--------------------------------------------------------------------------

  key             type   meaning
  --------------  -----  ----------------------------------------------------
  "size"          uint   N: grid points per axis. A complete table has
                         N * N * N entries. N >= 2 for a usable table.
  "components"    uint   always 3: each entry is a red, green, blue triplet.
  "fastest_axis"  str    always "red": the red input index varies fastest.

--------------------------------------------------------------------------
2. The section
--------------------------------------------------------------------------

  name     dtype   shape   stride   size
  -------  ------  ------  -------  -------
  "table"  "f32"   [L]     4        4 * L

  L little-endian IEEE-754 binary32 values, all finite. For a complete table
  L == 3 * N * N * N. (L is declared, as every size is; a table of another
  length is carried exactly as it was and is not usable for lookup - a reader
  that needs to look colours up treats the adjustment as changing nothing.)

  The entry for input grid point (r, g, b), each index in 0..N-1, starts at
  value index

      ((b * N + g) * N + r) * 3

  and holds the output red, green, blue, in that order. Grid index i stands for
  the input value i / (N - 1). Inputs and outputs are colour values on the 0.0
  to 1.0 scale (outputs may slightly exceed it).

--------------------------------------------------------------------------
3. Looking a colour up
--------------------------------------------------------------------------

  For an input (R, G, B) in 0.0..1.0: scale each to the grid, p = R * (N - 1)
  and so on; take the 8 surrounding grid entries and interpolate - trilinearly
  when the layer's `tetrahedral` is false, tetrahedrally (the unit cube split
  into six tetrahedra along its main diagonal) when it is true. Inputs outside
  0.0..1.0 are clamped to the grid.

--------------------------------------------------------------------------
4. Writing one
--------------------------------------------------------------------------

  Header {size: N, components: 3, fastest_axis: "red"} plus the envelope's own
  keys; one section "table" of 3 * N^3 floats in the order of section 2. The
  identity table has entry (r, g, b) = (r / (N-1), g / (N-1), b / (N-1)).
